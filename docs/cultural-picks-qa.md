# Cultural Pick — implementation and QA

7 October 2026. Existing application extended; no new authentication method, AI, scraping or album artwork provider. Implementation and local QA complete; hosted account acceptance remains pending.

1. **Architecture.** `types/pick.ts` discriminates film, TV, book and album. Normalization, requests, provider pools, selection and persistence live in `lib/picks`. One optional Cultural Pick joins the existing finite edition; provider failure omits it without preventing the magazine.
2. **TMDB.** Server-only bearer token; factual title, director/creator, year, genres and optional poster. No overview, review, rating or invented copy. The credential is currently absent, so real TMDB selection has NOT been verified. Discover pools cover two date ranges with genre mapping and a minimum vote count; these are bounded discovery pools, not comprehensive recommendations.
3. **Open Library.** Work identity, title, authors, first publication year and optional direct Covers API image. Daily deterministic search ordering, focused subject and explicit fields. Missing cover/year/author works; failed images collapse without placeholders. Subject classifications can be broad or noisy.
4. **MusicBrainz.** Actual release-group Albums, stable MBID, artist credits and year. Compilations/interviews/DJ mixes/mixtapes/broadcasts excluded. Live album release groups remain eligible. Real metadata requests succeeded.
5. **Request behavior.** All three metadata caches revalidate after 24 hours. Requests use a 10-second timeout, bounded response bodies and restricted provider hosts. MusicBrainz has a local serial queue plus PostgreSQL reservations shared by app processes, 1,100ms spacing, a bounded five-second queue and fail-closed behavior when reservation is unavailable. A configured contact identifies the app in User-Agent. This requires a shared Supabase database across deployed instances.
6. **No album imagery.** No Cover Art Archive, album cover fetch, album placeholder, artwork scrape or generated image.
7. **Eligibility.** Music directly prioritizes album; otherwise Books prioritizes book; otherwise Film prioritizes film/TV. Other selected interests map explicitly to cultural formats and book subjects/movie genres. Provider failures fall through eligible formats. TV mapping currently distinguishes science fiction from drama; it is intentionally limited.
8. **Determinism.** Date, sorted interests, stable provider IDs and refresh counter seed ordering. Deterministic within the available cached pool; upstream changes and daily provider sorting can change later pools.
9. **Anti-repetition.** Current identities are hard exclusions. The five previous account issues and bounded accepted same-day revision history prefer fresh items, with old history as a soft fallback when candidates run out. Guests retain current-day accepted history only.
10. **Another Pick.** Quiet replacement control; complete item replaced atomically, including ID, title, creators, image, attribution and Save identity. Failure keeps current content. A real guest API sequence produced album → book → different book, revision 2, with all story sections and other cultural modules unchanged.
11. **Revisions/Archive.** Account refresh appends an owner-scoped accepted revision; immutable original composition survives. Archive reconstructs accepted identities. TMDB records persist references only and hydrate metadata through the bounded provider cache, so historical identity is fixed while current provider metadata may change or become unavailable. Other cultural snapshots retain metadata. Legacy accepted issues are preserved rather than regenerated simply to add a new module.
12. **Detail pages.** `/explore/film/[id]`, `/explore/tv/[id]`, `/explore/book/[id]`, `/explore/album/[id]`; factual details, source link, Save, back link and calm unavailable state. Invalid identifiers do not become arbitrary provider URLs.
13. **Guest Save.** Visible button opens a small inline sign-in invitation, without automatic navigation. Magic link can return to the cultural detail; user presses Save again.
14. **Guest persistence removed.** Saved is account-only. The old Saved key is removed when the app hydrates; no new guest Saved writes. Guest preferences/current-day magazine remain available.
15. **Merge removed.** Guest library merge UI, API branch and repository method removed. Migration revokes the legacy merge RPC grant. Historical migration/parser regression tests remain; they do not re-enable the product flow. Explicit device-interest transfer remains separate.
16. **Authenticated Save.** Server revalidates cultural identity against its provider before account mutation. SQL guards and owner RLS apply. Embedded PostgreSQL verifies cultural Saves and cross-owner isolation; real hosted Save/logout/returning-login is still unverified.
17. **Saved model.** Existing union adds film, TV, book and album; canonical IDs deduplicate correctly. TMDB Saved rows contain references rather than indefinitely retained provider snapshots.
18. **Credits.** Sources separates editorial and cultural providers. Unmodified official TMDB logo and exact required disclaimer appear with noncommercial notice. Open Library and MusicBrainz link back; provider terms are not presented as CC0 licenses. See [TMDB FAQ](https://developer.themoviedb.org/docs/faq), [TMDB terms](https://www.themoviedb.org/api-terms-of-use), [Open Library API guidance](https://openlibrary.org/developers/api), and [MusicBrainz rate limits](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting). Cache expiry is explicitly bounded; TMDB app snapshots expire within 150 days, while server cache revalidates daily and database records keep references only.
19. **Migrations.** Existing 001/002 unchanged. User reports hosted 002 and new `202610070003_cultural_picks.sql` applied; real MusicBrainz reservations confirm the shared limiter is reachable. New additive `202610070004_tmdb_references.sql` replaces permanent TMDB metadata snapshots with references. Its hosted application is pending confirmation. Do not edit applied migrations.
